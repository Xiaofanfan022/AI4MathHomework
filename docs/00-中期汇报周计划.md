## 1. 汇报的验收标准（倒推）

5 分钟 ≈ 8~10 页 PPT，实际讲 4 分 30 秒。必须回答四个问题：

1. **你想研究什么数学问题？为什么它值得研究？**（30s）
2. **你的智能体长什么样？为什么这样设计？**（90s，架构图）
3. **它跑出来什么？**（120s，**核心图 + 真实数据**）
4. **你学到了什么 / 下一步做什么？**（60s）

> 判分重点不是「解决了问题」，而是「体现了运行与迭代」。
> 所以：**一张「第 1 轮到第 N 轮，成功率从 x% 涨到 y%」的图，比任何文字都有说服力。**

## 2. 选题

### 推荐：Ramanujan-Agent —— 数学常数恒等式的「猜想–验证–证明」闭环智能体

**问题域**：给定数学常数（π, e, ζ(3), Catalan G, ln2 …），自动发现形如

$$\pi = \cfrac{4}{1+\cfrac{1^2}{3+\cfrac{2^2}{5+\cdots}}}\qquad\text{或}\qquad \sum_{n\ge0}\frac{a_n}{b_n}=\zeta(3)$$

的恒等式，并判断它是**已知的 / 新的 / 可证的**。

**为什么选它（对 5 分钟汇报最友好）**：

| 优势 | 说明 |
|---|---|
| 算力极低 | 纯 CPU，一次实验几分钟，笔记本就能跑 |
| **验证是客观的** | 高精度数值比对，对错一目了然，不需要人来判断 |
| **天然有迭代叙事** | 第 1 轮 LLM 瞎猜 → 数值不过 → 反思重试 → 命中率上升 |
| **有真实的开放问题背景** | Ramanujan Machine（Raayoni et al., *Nature* 2021）就是这条路线，可引用、可对比 |
| **失败本身就是结论** | 「数值验证很便宜，形式化证明才是瓶颈」——这是能讲出来的洞察 |
| 可视化漂亮 | 收敛曲线、命中率柱状图、公式卡片 |

**诚实的预期结果**（写进 PPT，不要吹）：
- 智能体能稳定重新发现若干已知公式（如 Machin 类公式、ζ(2)=π²/6 的连分数）；
- 会产出「数值成立但证不出来」的候选式；
- 形式化证明成功率很低 —— 这正是下一步工作。

### 备选 A：组合构造搜索智能体（Heilbronn 三角形 / no-three-in-line）
LLM 出启发式 + 局部搜索，找更优构型。优点是有明确"最好已知值"可对比；缺点是代码量大，6 天内风险高。

### 备选 B：数论实验智能体（Erdős–Straus / Collatz 停时统计）
让 agent 自己设计实验、跑数据、画图、写结论。优点是门槛最低；缺点是"智能体"的味道偏淡，容易被问"这跟脚本有什么区别"。

> **建议选推荐方案。** 它同时满足「有数学深度」和「6 天内做得完」。

## 3. 系统设计（一页架构图）

```
                 ┌─────────────────────────────┐
   用户/任务 ───▶ │  Planner（拆解子目标）        │
                 └──────────────┬──────────────┘
                                ▼
                 ┌─────────────────────────────┐
                 │  Executor（ReAct 循环）      │◀── Memory / Trace
                 │  Thought → Action → Obs      │
                 └──────────────┬──────────────┘
                                ▼
        ┌───────────────────────────────────────────────┐
        │  Tool Layer                                    │
        │  python_exec      沙箱执行，超时+资源限制        │
        │  hp_eval          mpmath 高精度求值（dps=200）  │
        │  pslq             整数关系检测（发现线性关系）    │
        │  sympy_prove      化简 / 符号验证               │
        │  oeis_lookup      查 OEIS 判新颖性              │
        │  arxiv_search     文献检索                      │
        │  plot / write_note 产出图表与实验笔记            │
        └───────────────────────────────────────────────┘
                                ▼
                 ┌─────────────────────────────┐
                 │  Critic（反思：为什么错了？） │──┐
                 └─────────────────────────────┘  │ 迭代
                                ▲                 │
                                └─────────────────┘
```

**相比 `FirstAgentTest.py` 的四处升级**（这也是"学到什么"的素材）：

1. **正则解析 → 原生 function calling**：正则脆弱，工具参数一复杂就崩。
2. **单轮 5 次循环 → 带反思的多轮迭代**：失败要能自己定位原因。
3. **纯文本工具 → 能执行代码的工具**：数学智能体必须能算。
4. **print 调试 → 结构化 trace（JSONL）**：每次 Thought/Action/Observation/耗时/token 全落盘，可直接生成实验图。
